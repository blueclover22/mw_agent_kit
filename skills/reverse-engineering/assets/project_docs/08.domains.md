# Domains — Feature Domain Index

> Template: an index for managing **feature/subsystem domain** guides specific to this project (e.g. payments `payments`, hardware integration `hw_interface`, local DB `local_db` (SQLite), inventory `inventory`). The actual domain guides live in the [`domains/`](domains/) folder, one file per domain. Delete this notice. Permanent guide.

While 06 (UI layer) and 07 (core layer) are **horizontal (layer)** conventions, a feature domain is a slice that cuts **vertically** across multiple layers (payments = UI + core + contracts). Because the count varies per project and keeps growing, they live in the **`domains/` folder outside the numbering scheme** so that adding documents does not shift the core (09–13) numbers.

## 2. Authoring Rules

- Create a new domain by copying [`domains/_template.md`](domains/_template.md) to `domains/<domain>-guide.md`. **Do not assign numbers** — free to add/remove, no renumbering of core documents.
- For domain terms see [`01.Glossary.md`](01.Glossary.md), for external contracts [`05.framework-api.md`](05.framework-api.md), for call chains [`12.process-guide.md`](12.process-guide.md) (the SSOT lives there).
- `domains/` files are **leaf documents** — they reference the core one-way; the core does not back-reference them (§00 related_to exception, same as 00 and 13).
